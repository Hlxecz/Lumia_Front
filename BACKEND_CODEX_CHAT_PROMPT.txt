이 저장소에 채팅 API를 구현해줘. 직접 파일을 수정해서 적용해줘.

[목표]
- 프론트 앱이 이미 POST /api/chat/completions 를 호출하고 있다.
- 요청 바디는 { "message": "사용자 입력" }
- 응답 바디는 최소 { "reply": "모델 응답 문자열" } 형태로 맞춰줘.
- OpenAI API 키는 프론트가 아니라 백엔드에서만 사용해야 한다.

[요구사항]
- Spring Boot 프로젝트 구조에 맞게 구현해줘.
- 가능하면 기존 패키지 구조, 예외 처리 방식, 로깅 스타일, DTO 네이밍 규칙을 따라줘.
- 필요한 경우 새 파일 생성 및 기존 설정 파일 수정까지 해줘.
- 하드코딩된 API 키는 절대 넣지 말고, 환경변수 OPENAI_API_KEY 또는 설정 프로퍼티를 통해 주입받아라.
- 프론트는 현재 백엔드 /api/chat/completions 만 호출하도록 되어 있으니, 이 계약을 깨지 말아라.
- 응답은 가장 단순하게 { "reply": "..." } 로 내려주면 된다.
- 사용자가 로그인한 상태일 수 있으므로, 기존 인증 체계가 있으면 그 구조를 해치지 않는 선에서 맞춰줘. 다만 최소 구현은 인증된 사용자의 요청을 정상 처리하는 수준이면 된다.
- 입력값 message 가 비어 있으면 400을 반환해줘.
- OpenAI 호출 실패 시 5xx로만 던지지 말고, 적절한 예외 처리와 로그를 넣어줘.
- 가능하면 타임아웃도 설정해줘.
- CORS나 보안 설정 때문에 이 엔드포인트가 막히면 필요한 최소 설정도 반영해줘.
- 기존에 이미 HTTP 클라이언트(WebClient, RestClient, RestTemplate, OkHttp 등)가 있으면 재사용하고, 없으면 프로젝트에 맞는 최소 방식으로 구현해줘.
- OpenAI 호출 로직은 서비스 클래스로 분리해줘.

[구현 범위]
1. Controller
- POST /api/chat/completions

2. DTO
- 요청 DTO: message: String
- 응답 DTO: reply: String

3. Service
- OpenAI Chat Completions 또는 Responses API를 호출해서 텍스트 응답을 받아와라.
- 사용 모델은 프로젝트에 맞는 현재 적절한 텍스트 생성 모델을 선택하되, 모델명은 설정으로 분리 가능하면 분리해줘.

4. Config
- OPENAI_API_KEY
- 필요하면 OPENAI_MODEL
- 필요하면 timeout 설정

5. 검증
- 빌드/컴파일 가능한 상태까지 맞춰줘.
- 가능하면 간단한 테스트 또는 최소한의 검증 포인트를 남겨줘.

[프론트 연동 정보]
- 프론트는 Authorization Bearer 토큰을 보낼 수 있다.
- 프론트는 응답에서 reply 필드를 우선 읽는다.
- 따라서 응답 예시는 아래처럼 맞춰라:
  { "reply": "안녕하세요. 무엇을 도와드릴까요?" }

[작업 방식]
- 먼저 현재 백엔드의 패키지 구조, 보안 설정, HTTP 클라이언트 사용 패턴을 확인해라.
- 그다음 필요한 파일만 수정/추가해라.
- 패키지명, 보안 설정, 빌드도구(Gradle/Maven)는 저장소를 읽고 자동으로 맞춰줘.
- 마지막 답변에는 아래를 꼭 포함해라:
  1. 변경한 파일 목록
  2. 환경변수/설정 방법
  3. 실행 또는 테스트 방법
  4. 프론트와 맞춰진 API 요청/응답 예시

[주의사항]
- 프론트에 비밀키를 내려주지 마라.
- 임시 mock 응답으로 끝내지 말고 실제 OpenAI 호출까지 연결해라.
- 저장소의 기존 코딩 스타일과 예외 처리 방식을 최대한 유지해라.
