# 4. Concept of Operation

[⬅️ Back to Contents](./Conceptualization.md)

---

## 1) 회원가입 (Sign Up)
| 구분 | 내용 |
| :--- | :--- |
| **Purpose** | 신규 사용자를 시스템에 안전하게 등록하기 위함. |
| **Approach** | 회원가입 정보 수신 시 중복 아이디/이메일을 검증하고, 비밀번호를 암호화하여 기본 설정과 함께 DB에 저장한다. |
| **Dynamics** | 앱을 최초로 실행하여 회원가입을 시도할 때. |
| **Goals** | 보안이 강화된 사용자 계정을 생성하고 초기 이용 환경을 구축한다. |

## 2) 로그인 (Login)
| 구분 | 내용 |
| :--- | :--- |
| **Purpose** | 등록된 사용자의 신원을 확인하고 서비스 접근 권한을 부여함. |
| **Approach** | ID/PW 대조 시 암호화된 비밀번호를 비교 검증하며, JWT(Access/Refresh) 토큰을 발급하여 보안 세션을 관리한다. |
| **Dynamics** | 앱을 실행하거나 토큰 만료로 인해 재인증이 필요한 때. |
| **Goals** | 인가된 사용자에게만 시스템 기능을 허용하는 안전한 인증 체계를 구현한다. |

## 3) 정기 질문 발급 (Receive Scheduled Question)
| 구분 | 내용 |
| :--- | :--- |
| **Purpose** | 사용자의 정기적인 감정 회고 습관을 유도하기 위함. |
| **Approach** | 서버가 사용자의 알림 시간, 마지막 발급 기록, 미응답 상태를 확인하여 조건 만족 시 정기 질문 인스턴스를 생성 및 제공한다. |
| **Dynamics** | 사용자가 사전에 설정한 알림 시각이 되었을 때. |
| **Goals** | 규칙적인 질문 제공을 통해 일관된 자기 성찰 환경을 조성한다. |

## 4) 추가 질문 발급 (Receive On-Demand Question)
| 구분 | 내용 |
| :--- | :--- |
| **Purpose** | 사용자가 원할 때 능동적으로 추가적인 감정 점검을 지원함. |
| **Approach** | 사용자 요청 시 당일 추가 질문 발급 여부를 서버에서 확인한 후, 특정 질문을 DB에서 가져와 제공한다. |
| **Dynamics** | 사용자가 앱 내에서 '추가 질문 받기' 버튼을 클릭했을 때. |
| **Goals** | 일일 1회 제한 로직을 준수하며 유연한 감정 기록 기회를 제공한다. |

## 5) 답변 제출 및 보상 (Submit Answer)
| 구분 | 내용 |
| :--- | :--- |
| **Purpose** | 사용자가 작성한 회고 데이터를 안전하게 보관하고 활동 보상을 제공함. |
| **Approach** | 답변 내용 및 감정 태그를 저장하고, DB 트랜잭션을 통해 코인 지급과 캐릭터 성장 수치를 데이터 불일치 없이 일괄 갱신한다. |
| **Dynamics** | 사용자가 질문에 대한 답변 작성을 완료하고 제출 버튼을 눌렀을 때 |
| **Goals** | 데이터 무결성이 보장된 답변 저장 및 보상 처리 시스템을 구축한다. |

## 6) 설정 관리 (View/Update Settings)
| 구분 | 내용 |
| :--- | :--- |
| **Purpose** | 사용자마다 개인화된 알림 및 앱 이용 환경을 제공하기 위함. |
| **Approach** | 현재 설정을 조회하거나 알림 주기, 시간, 푸시 사용 여부 변경 요청을 수신하여 사용자 설정 테이블의 데이터를 갱신한다. |
| **Dynamics** | 사용자가 설정 메뉴에 진입하거나 옵션 정보를 수정할 때. |
| **Goals** | 사용자 편의에 맞춘 맞춤형 환경 관리 기능을 구현한다. |

## 7) 아이템 구매 (Purchase Item)
| 구분 | 내용 |
| :--- | :--- |
| **Purpose** | 활동 보상으로 얻은 재화의 소비를 통해 서비스 이용 재미를 극대화함. |
| **Approach** | 아이템 가격, 중복 구매 여부, 코인 잔액을 검증한 후 연산을 통해 구매 내역 반영 및 코인 차감을 처리한다. |
| **Dynamics** | 사용자가 상점에서 아이템 구매 버튼을 눌러 확정했을 때. |
| **Goals** | 안정적인 상점 구매 로직과 재화 관리 기능을 구현한다. |

## 8) 게시글 작성 (Create Post)
| 구분 | 내용 |
| :--- | :--- |
| **Purpose** | 사용자 간의 긍정적인 경험 공유와 정서적 유대를 지원함. |
| **Approach** | 작성된 텍스트를 외부 FastAPI 필터 서버로 전송하여 검열을 거친 뒤, 승인된 경우에만 커뮤니티 DB에 게시글을 저장한다. |
| **Dynamics** | 익명 커뮤니티 탭에서 새 글을 작성하고 등록 요청을 보낼 때. |
| **Goals** | 필터링 기술을 활용하여 안전하고 건전한 소통 환경을 조성한다. |

## 9) 댓글 작성 (Create Comment)
| 구분 | 내용 |
| :--- | :--- |
| **Purpose** | 게시글 기반의 활발한 정서적 상호작용과 지지를 지원함. |
| **Approach** | 댓글 내용을 필터링 후 저장하며, 본인 확인 로직을 통해 작성자 본인만 수정 및 삭제가 가능하도록 권한을 철저히 검증한다. |
| **Dynamics** | 게시글 상세 페이지 하단에서 댓글 입력을 완료했을 때. |
| **Goals** | 사용자 간의 신뢰도 높은 소셜 상호작용 기능을 구현한다. |

## 10) AI 공감 채팅 (AI Chat)
| 구분 | 내용 |
| :--- | :--- |
| **Purpose** | 24시간 언제 어디서나 즉각적인 공감과 위로 서비스를 제공함. |
| **Approach** | 백엔드에서 OpenAI API 키를 안전하게 관리하며, 사용자 메시지에 반응하는 비판단적이고 공감적인 답변을 생성하여 반환한다. |
| **Dynamics** | 사용자가 AI 친구 메뉴에 접속하여 대화를 시도할 때. |
| **Goals** | 최신 AI 기술을 연동하여 실시간 정서 케어 생태계를 구축한다. |
