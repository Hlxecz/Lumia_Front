# 5. Problem statement

[⬅️ Back to Contents](./Conceptualization.md)

---

본 소프트웨어를 기획하고 설계하는 과정에서 발생할 수 있는 주요 문제점들을 분석하였다. 특히 백엔드 시스템의 안정성과 사용자의 경험(UX) 측면에서 반드시 해결해야 할 n가지 과제들을 다음과 같이 정의한다.

### Problem#1. Data Integrity & Rewards (보상 데이터 무결성)
서비스의 핵심인 '감정 회고'를 지속하게 하는 원동력은 캐릭터 성장과 코인 보상이다. 하지만 네트워크 지연이나 예외 상황으로 인해 사용자가 답변은 제출했으나 보상(코인, 경험치)이 지급되지 않는 불일치가 발생한다면 서비스 신뢰도에 치명적인 타격을 줄 수 있다. 이를 방지하기 위해 답변 저장과 보상 지급 로직을 하나의 트랜잭션(Transaction)으로 묶어 '전부 성공하거나 전부 실패'하게 설계하여 데이터의 원자성을 보장하는 구성이 필수적이다.

### Problem#2. External API Dependency (외부 API 의존성 및 장애 대응)
루미아는 OpenAI의 생성형 AI와 FastAPI 필터링 서버라는 두 가지 외부 시스템에 크게 의존한다. 만약 외부 서버에서 타임아웃이 발생하거나 API 호출 한도를 초과할 경우, 사용자의 게시글 등록이나 AI 채팅 기능이 멈춰버리는 상황이 생길 수 있다. 따라서 이러한 장애 상황에 대비하여 사용자에게 적절한 안내 메시지를 출력하는 예외 처리(Exception Handling)를 강화하고, API 응답 대기 시간 동안에도 앱이 멈추지 않도록 비동기 통신 방식을 채택하여 시스템의 가용성을 높여야 한다.

### Problem#3. Authentication & Security (보안 및 인증 관리)
사용자의 내밀한 감정 답변과 개인 정보를 다루는 만큼, 보안은 가장 우선시되어야 할 과제이다. 단순히 로그인 기능을 구현하는 것에서 나아가, JWT(Access/Refresh Token) 기반의 인증 체계를 통해 매 요청마다 보안성을 검증해야 한다. 특히 프론트엔드 코드에 OpenAI API 키와 같은 민감한 정보를 노출하지 않도록, 모든 외부 통신은 백엔드 서버를 경유하게 설계하여 보안 사고의 위험을 원천적으로 차단하는 전략이 필요하다.

### Problem#4. Retention Maintenance (사용자 리텐션 유지)
단순한 텍스트 기록 서비스는 사용자가 금방 실증을 느끼고 이탈하기 쉽다는 단점이 있다. 이를 기술적으로 보완하기 위해 스케줄링(Scheduling) 기능을 활용하여 매일 정해진 시간에 맞춤형 질문 푸시 알림을 보내는 시스템적 장치를 구축해야 한다. 또한 사용자의 발급 이력을 DB에서 실시간으로 대조하여 질문이 중복되거나 누락되지 않도록 '지속 가능한 리텐션'을 위한 데이터 로직 설계에 집중해야 한다.
