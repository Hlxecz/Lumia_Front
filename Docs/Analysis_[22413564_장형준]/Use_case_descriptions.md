# Use Case #1 : Login

## 1. GENERAL CHARACTERISTICS

| 항목                       | 내용                                                                         |
| :------------------------- | :--------------------------------------------------------------------------- |
| **Summary**                | 사용자가 시스템에 접속하기 위해 등록된 계정 정보를 입력하고 인증을 받는 과정 |
| **Scope / Level**          | Lumia System / User Level                                                    |
| **Author**                 | 장형준                                                                       |
| **Last Update**            | 2026-04-28                                                                   |
| **Status**                 | Analysis                                                                     |
| **Primary Actor**          | 회원                                                                         |
| **Preconditions**          | 사용자가 앱을 실행한 상태이며, 회원가입(Sign up)이 완료되어 있어야 한다.     |
| **Trigger**                | 사용자가 메인 화면에서 '로그인' 버튼을 클릭한다.                             |
| **Success Post Condition** | 사용자가 시스템 인증에 성공하여 메인 대시보드로 이동한다.                    |
| **Failed Post Condition**  | 인증 실패 메시지가 출력되며, 로그인되지 않은 상태로 로그인 화면에 머무른다.  |

## 2. MAIN SUCCESS SCENARIO

| Step | Action                                                          |
| :--- | :-------------------------------------------------------------- |
| 1    | 사용자가 아이디(이메일)와 비밀번호를 입력한다.                  |
| 2    | 사용자가 '로그인 확인' 버튼을 누른다.                           |
| 3    | 시스템은 데이터베이스에 저장된 사용자 정보와 입력값을 비교한다. |
| 4    | 시스템은 사용자 인증 세션을 생성한다.                           |
| 5    | 시스템은 사용자를 로그인 후 첫 화면(메인 화면)으로 이동시킨다.  |

## 3. EXTENSION SCENARIOS

- **3a. 로그인 정보 불일치**: 시스템은 오류 메시지를 출력하고 다시 입력하게 한다.
- **3b. 비밀번호 분실**: 사용자가 '비밀번호 찾기'를 누르면 관련 프로세스로 유도한다.

## 4. RELATED INFORMATION

| 항목                   | 내용                                 |
| :--------------------- | :----------------------------------- |
| **Priority**           | High                                 |
| **Frequency**          | 앱 접속 시마다 발생                  |
| **Issues**             | 자동 로그인 기능 포함 여부 검토 필요 |
| **Performance Target** | 인증 요청 후 2초 이내 결과 응답      |

# Use Case #2 : Find ID

## 1. GENERAL CHARACTERISTICS

| 항목                       | 내용                                                                                       |
| :------------------------- | :----------------------------------------------------------------------------------------- |
| **Summary**                | 사용자가 아이디(이메일)를 잊어버린 경우, 본인 확인 정보를 통해 아이디를 확인하는 과정      |
| **Scope / Level**          | Lumia System / User Level                                                                  |
| **Author**                 | 장형준                                                                                     |
| **Last Update**            | 2026-04-28                                                                                 |
| **Status**                 | Analysis                                                                                   |
| **Primary Actor**          | 회원                                                                                       |
| **Preconditions**          | 사용자가 로그인 화면에 접속해 있으며, 가입 시 등록한 보조 수단(전화번호 등)이 있어야 한다. |
| **Trigger**                | 사용자가 로그인 화면에서 '아이디 찾기' 버튼을 클릭한다.                                    |
| **Success Post Condition** | 시스템이 사용자의 아이디를 화면에 표시하거나 등록된 수단으로 전송한다.                     |
| **Failed Post Condition**  | 일치하는 정보가 없다는 메시지를 출력하고 아이디 찾기 화면에 머무른다.                      |

## 2. MAIN SUCCESS SCENARIO

| Step | Action                                                                          |
| :--- | :------------------------------------------------------------------------------ |
| 1    | 사용자가 이름과 가입 시 등록한 정보(전화번호 등)를 입력한다.                    |
| 2    | 사용자가 '아이디 찾기 확인' 버튼을 누른다.                                      |
| 3    | 시스템은 데이터베이스에서 입력된 정보와 일치하는 사용자를 조회한다.             |
| 4    | 시스템은 조회된 사용자의 아이디(이메일) 정보를 마스킹 처리하여 화면에 보여준다. |
| 5    | 사용자가 확인 후 다시 로그인 화면으로 이동한다.                                 |

## 3. EXTENSION SCENARIOS

- **3a. 일치하는 사용자 정보 없음**: 시스템은 "입력하신 정보와 일치하는 아이디가 없습니다"라는 메시지를 출력한다.
- **3b. 필수 항목 미입력**: 사용자가 정보를 입력하지 않고 확인을 누르면, 시스템은 해당 항목을 입력하라는 경고를 띄운다.

## 4. RELATED INFORMATION

| 항목                   | 내용                                                                       |
| :--------------------- | :------------------------------------------------------------------------- |
| **Priority**           | Medium                                                                     |
| **Frequency**          | 아이디를 분실한 경우에만 간헐적으로 발생                                   |
| **Issues**             | 개인정보 보호를 위해 아이디 전체를 보여줄지 일부 마스킹 처리할지 결정 필요 |
| **Performance Target** | 조회 요청 후 3초 이내 결과 응답                                            |

# Use Case #3 : Sign up

## 1. GENERAL CHARACTERISTICS

| 항목                       | 내용                                                                                    |
| :------------------------- | :-------------------------------------------------------------------------------------- |
| **Summary**                | 새로운 사용자가 시스템을 이용하기 위해 자신의 인적 사항을 등록하고 계정을 생성하는 과정 |
| **Scope / Level**          | Lumia System / User Level                                                               |
| **Author**                 | 장형준                                                                                  |
| **Last Update**            | 2026-04-28                                                                              |
| **Status**                 | Analysis                                                                                |
| **Primary Actor**          | 비회원(Guest)                                                                           |
| **Preconditions**          | 사용자가 앱을 설치하고 실행한 상태여야 한다.                                            |
| **Trigger**                | 사용자가 시작 화면에서 '회원가입' 또는 '계정 만들기' 버튼을 클릭한다.                   |
| **Success Post Condition** | 새로운 사용자 계정이 데이터베이스에 저장되고, 자동 로그인되어 메인 화면으로 이동한다.   |
| **Failed Post Condition**  | 회원가입 실패 메시지가 출력되며, 계정이 생성되지 않은 상태로 가입 화면에 머무른다.      |

## 2. MAIN SUCCESS SCENARIO

| Step | Action                                                                |
| :--- | :-------------------------------------------------------------------- |
| 1    | 사용자가 이메일, 비밀번호, 닉네임 등 필수 정보를 입력한다.            |
| 2    | 사용자가 이용약관 및 개인정보 처리방침에 동의를 체크한다.             |
| 3    | 사용자가 '가입하기' 버튼을 누른다.                                    |
| 4    | 시스템은 입력된 이메일의 중복 여부 및 비밀번호 유효성을 검증한다.     |
| 5    | 시스템은 새로운 사용자 레코드를 생성하고 가입 완료 메시지를 보여준다. |

## 3. EXTENSION SCENARIOS

- **4a. 이메일 중복**: 시스템은 이미 존재하는 이메일임을 알리고 다른 이메일 입력을 요청한다.
- **4b. 비밀번호 유효성 미달**: 시스템은 비밀번호 정책(문자, 숫자 조합 등)에 맞지 않음을 알린다.
- **4c. 필수 약관 미동의**: 사용자가 필수 약관에 동의하지 않은 경우 가입을 진행하지 않는다.

## 4. RELATED INFORMATION

| 항목                   | 내용                                                      |
| :--------------------- | :-------------------------------------------------------- |
| **Priority**           | High                                                      |
| **Frequency**          | 신규 사용자 유입 시 발생                                  |
| **Issues**             | 이메일 인증 절차(OTP 또는 링크)를 포함할지 여부 결정 필요 |
| **Performance Target** | 가입 버튼 클릭 후 3초 이내 처리 완료                      |

# Use Case #4 : Logout

## 1. GENERAL CHARACTERISTICS

| 항목                       | 내용                                                                         |
| :------------------------- | :--------------------------------------------------------------------------- |
| **Summary**                | 사용자가 시스템 이용을 마치고 현재의 인증 세션을 종료하는 과정               |
| **Scope / Level**          | Lumia System / User Level                                                    |
| **Author**                 | 장형준                                                                       |
| **Last Update**            | 2026-04-28                                                                   |
| **Status**                 | Analysis                                                                     |
| **Primary Actor**          | 회원                                                                         |
| **Preconditions**          | 사용자가 로그인되어 있는 상태여야 한다.                                      |
| **Trigger**                | 사용자가 설정 또는 프로필 화면에서 '로그아웃' 버튼을 클릭한다.               |
| **Success Post Condition** | 사용자의 세션이 파기되고, 앱의 초기 접속 화면 또는 로그인 화면으로 이동한다. |
| **Failed Post Condition**  | 시스템 오류로 세션 파기에 실패할 경우, 로그인 상태를 유지하며 에러를 알린다. |

## 2. MAIN SUCCESS SCENARIO

| Step | Action                                                              |
| :--- | :------------------------------------------------------------------ |
| 1    | 사용자가 앱 내 설정 메뉴에서 '로그아웃' 버튼을 누른다.              |
| 2    | 시스템은 사용자에게 정말로 로그아웃할 것인지 확인 팝업을 띄운다.    |
| 3    | 사용자가 '확인'을 선택한다.                                         |
| 4    | 시스템은 서버에 저장된 사용자의 인증 토큰 및 세션 정보를 삭제한다.  |
| 5    | 시스템은 로그아웃 완료 메시지와 함께 초기 로그인 화면으로 전환한다. |

## 3. EXTENSION SCENARIOS

- **3a. 로그아웃 취소**: 사용자가 확인 팝업에서 '취소'를 누르면 로그아웃을 진행하지 않고 이전 화면으로 돌아간다.
- **4a. 네트워크 연결 오류**: 세션 삭제 중 네트워크가 끊기면 시스템은 재시도를 요청하거나 로컬 세션을 우선 삭제한다.

## 4. RELATED INFORMATION

| 항목                   | 내용                                                             |
| :--------------------- | :--------------------------------------------------------------- |
| **Priority**           | Low                                                              |
| **Frequency**          | 사용자가 앱 이용을 종료할 때마다 발생                            |
| **Issues**             | 자동 로그인 해제 여부 및 기기 내 캐시 데이터 삭제 범위 결정 필요 |
| **Performance Target** | 로그아웃 버튼 클릭 후 1초 이내 처리 완료                         |

# Use Case #5 : Withdrawal

## 1. GENERAL CHARACTERISTICS

| 항목                       | 내용                                                                         |
| :------------------------- | :--------------------------------------------------------------------------- |
| **Summary**                | 사용자가 시스템 이용을 영구히 중단하기 위해 자신의 계정 정보를 삭제하는 과정 |
| **Scope / Level**          | Lumia System / User Level                                                    |
| **Author**                 | 장형준                                                                       |

| **Status**                 | Analysis                                                                     |
| **Primary Actor**          | 회원                                                                         |
| **Preconditions**          | 사용자가 로그인되어 있는 상태여야 한다.                                      |
| **Trigger**                | 사용자가 설정 화면에서 '회원 탈퇴' 버튼을 클릭한다.                          |
| **Success Post Condition** | 사용자의 모든 개인정보와 데이터가 삭제(또는 익명화)되고 계정이 파기된다.     |
| **Failed Post Condition**  | 시스템 오류로 탈퇴에 실패할 경우, 계정 상태를 유지하며 에러를 알린다.        |

## 2. MAIN SUCCESS SCENARIO

| Step | Action                                                                        |

| 2    | 시스템은 탈퇴 시 삭제되는 데이터와 주의사항을 안내하고 동의를 구한다.         |
| 3    | 사용자가 탈퇴 사유를 선택하고 '확인' 버튼을 누른다.                           |

| 5    | 시스템은 데이터베이스에서 해당 사용자의 정보를 삭제하고 완료 화면을 보여준다. |

## 3. EXTENSION SCENARIOS

- **3a. 탈퇴 동의 거부**: 사용자가 주의사항에 동의하지 않으면 탈퇴를 진행하지 않고 이전 화면으로 돌아간다.
- **4a. 비밀번호 불일치**: 본인 확인을 위한 비밀번호가 틀릴 경우, 시스템은 에러 메시지를 출력하고 탈퇴를 중단한다.

## 4. RELATED INFORMATION

| 항목                   | 내용                                                                        |
| :--------------------- | :-------------------------------------------------------------------------- |
| **Priority**           | Low                                                                         |
| **Frequency**          | 사용자가 서비스를 해지할 때 발생                                            |
| **Issues**             | 작성했던 익명 게시글과 일기를 즉시 삭제할지, 익명 상태로 유지할지 결정 필요 |

# Use Case #6 : Write Post

| 항목                       | 내용                                                                            |
| :------------------------- | :------------------------------------------------------------------------------ |
| **Summary**                | 사용자가 익명 커뮤니티 공간에 자신의 고민이나 생각 등을 담은 글을 게시하는 과정 |

| **Success Post Condition** | 게시글이 시스템에 저장되고, 커뮤니티 피드에 실시간으로 업데이트되어 노출된다.   |

## 3. EXTENSION SCENARIOS

- **1a. 필수 항목 미입력**: 제목이나 본문이 욕설 or 비어있는 경우 시스템은 경고 메시지를 띄우고 등록을 차단한다.
- **3a. 욕설 및 부적절한 언어 감지**: FastAPI 서버 검증 결과 비속어가 감지되면 "부적절한 표현이 포함되어 있어 게시할 수 없습니다."라는 에러 메시지를 출력하고 저장을 차단한다.
- **4a. 네트워크 오류**: 업로드 중 연결이 끊기면 시스템은 재시도를 요청한다.

## 4. RELATED INFORMATION

| 항목                   | 내용                                                                       |

| **Performance Target** | 서버 검증 포함 등록 버튼 클릭 후 2초 이내 게시 완료                        |
